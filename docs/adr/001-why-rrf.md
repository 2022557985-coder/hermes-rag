# ADR-001: 选择 RRF 而非线性加权融合

## 状态

已采纳

## 背景

在多路检索（稠密向量 + 稀疏 BM25）中，需要将两路结果融合为一个排序列表。常见的融合方法有：

1. **线性加权**：`score = w1 * dense_score + w2 * sparse_score`
2. **Reciprocal Rank Fusion (RRF)**：`score = 1/(k + rank)`

## 决策

选择 **改进的 RRF** 融合算法，`k=60`，支持动态权重调整。

## 理由

### 1. 分数尺度无关

稠密检索的余弦相似度（0-1）和 BM25 的 TF-IDF 分数（无上限）处于完全不同的尺度。线性加权需要复杂的归一化，而 RRF 只依赖排名，天然尺度无关。

### 2. 鲁棒性

RRF 对异常值不敏感。即使某一路检索返回了极高分数的噪声结果，RRF 也只会根据其排名给予有限权重，不会像线性加权那样被拉偏。

### 3. 动态权重

改进版 RRF 支持根据查询类型动态调整权重：
- 产品型号/编号查询 → BM25 权重 ↑（精确匹配更重要）
- 自然语言口语化 → 向量权重 ↑（语义理解更重要）

### 4. 实证支持

相关研究表明，RRF 在多个 TREC 数据集上优于线性加权和 Condorcet 融合。

## 替代方案

### 线性加权
- 优点：实现简单
- 缺点：需要分数归一化，不同检索器分数分布差异大

### 学习排序（LTR）
- 优点：理论最优
- 缺点：需要标注数据，训练成本高，不适合零样本场景

## 参数选择

`k=60` 是经验最优值。较大的 k 使排名靠前的结果权重更接近，较小的 k 加大排名差异的影响。60 在精度和区分度之间取得平衡。

## 后果

- 正面：融合结果稳定，无需手动调整分数归一化
- 负面：k 值需要根据数据集微调，但默认值已覆盖大多数场景
- 风险：极端情况下（如某一路完全失效），需要降级处理
